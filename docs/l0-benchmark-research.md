# L0 多表合成医院底座：调研与采用记录

日期：2026-10-19（官方资料检索于 2026-10-16）。本文件记录本次实施采用的方法与边界；数据生成、评测执行结果另以模块验证记录为准。

1. **目标与范围。** 以 `apps/medical-query/fixtures/l0` 的 47 项指标知识反向设计原始事实、关联路径和评测场景，保留现有 26 张核心表契约，再增加具有独立业务粒度的支撑表，使库规模超过 100 张表。新增表必须有业务作用和非空合成数据；近义表用于考察正确选表，不通过复制空表扩充数量。
2. **调研方式。** 已使用 Firecrawl developer 免额度索引查询 Synthea、OMOP、Spider 2.0；普通抓取额度已耗尽（查询时为 -19），因此通过可用网页工具补读下列官方资料。未下载患者明细、运行外部生成器或调用模型；本次只借用方法，不引入额外运行依赖。
3. **Synthea：采用纵向事件生成方法。** 官方项目按患者生命周期模拟就诊、诊断、用药、观察、检验和操作，支持随机种子、人口规模、参考日期与 CSV 导出。本项目采用固定 seed、固定时间锚点、先生成事件链再写表的思路；不引入其 Java 17+ 运行环境，也不将其美国默认人口与临床模块作为中国医院指标口径。项目许可证为 Apache-2.0，本次不复制其代码或数据。[官方 README](https://github.com/synthetichealth/synthea)
4. **OMOP：采用粒度与来源分离方法。** v5.4 规范区分患者、一次就诊和一对多的就诊细节；后者可表示住院期间转科，并通过外键关联。其事件表及原始代码、标准概念的区分，有助于避免把一个患者、一次住院和一次操作混为同一统计单位。本项目保留 L0 核心表，不整体迁移为 OMOP，不导入其词表；医院本地代码、版本与合成映射必须显式记录。[官方规范](https://ohdsi.github.io/CommonDataModel/cdm54.html)
5. **Spider 2.0：采用复杂目录与结果验证方法。** 官方任务包含大量字段、数据库元数据与业务文档，部分任务需要多步 SQL；其公开说明要求使用真实答案表时明确标注 oracle setting。本项目借用“大目录内筛表、查证字段和关系、验证最终结果”的评测方式；不引入 Snowflake、BigQuery 或 DBT 环境。标准答案、允许表集合和参考 SQL 只供外部评测器使用，不进入产品提示词。[官方介绍与评测说明](https://spider2-sql.github.io/)
6. **新增表围绕实际业务闭环。** 重点区分预约、改约、报到与叫号；入院医嘱、实际入院、转科、分床与实际出院；手术申请、排程、麻醉与完成；药品医嘱、发药、退药与实际消耗；收费、账务分录、发票、收款与医保结算；床位资产、维护状态与每日开放床位。检验、护理、人员、编码字典、资产、预算和能耗等表补充可追溯背景。计划记录不能替代完成事实，流水金额不能替代会计归属金额。
7. **事实一致性先于题目数量。** 生成器应固定 seed 和统计时间锚点，保留跨机构相同局部键、同人多次就诊、跨月住院、边界日期、取消或未完成事件、缺失值、冲销与版本变化等场景。机构内键采用复合关联；时间、外键、代码类型、单位与业务状态必须可校验。新表需声明行粒度、所属事件、时间字段、关联路径及与近义表的区别。
8. **合成假设与正式规范分开。** `mock_conventions.json` 的 `synthetic_test_design` 标记继续适用；固定月份、合成药品/病种编码、外部基准和场景排除约定不构成正式医院绑定。原始指标来源文件不因造数而补写。M0645 外部评分与 S012 人工评审等阻断场景应保留“不足以计算”的预期，不能靠随机数填成正式成绩。
9. **题集由场景反向生成，答案独立核对。** 先确定事实与困难点，再编写自然语言问题，分开检查指标识别、表字段选择、关联及过滤、最终可计算结果。数值答案需由独立参考 SQL 或明确基础量核对，不能由被测模型自产自评。只生成原始事实和必要的源系统参考数据，不向业务数据库写入 47 项预计算指标答案。
10. **已有 EHRSQL 只借结构与题型。** 本地题集可提供患者—住院—事件关系、时间筛选和多表查询场景的参考；其派生 MIMIC demo 数据、2100 年时间锚点与随机费用均不能充当本项目 L0 正式口径或数值金标准。新合成库和题集保持独立来源、版本与固定时间锚点。
11. **本次文档变更与验证边界。** 新增本调研记录，完整复核现有 `mock_schema.sql` 的 26 张核心表及相关合成约定，向实现者提供事件链与近义表建议。未修改来源规则、运行上游代码或声称新生成器已经通过验证；表数、非空覆盖、完整性、确定性与评测隔离仍须以实现完成后的实际验收为准。
