# 运行恢复与过滤条件修复记录

更新：2026-10-21。本轮修复发生在 136 题及 21 槽真实实验结束之后；旧报告保留原执行指纹，不能用本轮离线结果回填真实成绩。

1. 目标：修复控制账本已接受继续、Pi 暂停尚未解除时的恢复死锁，以及非默认在线队列保留量只在模型池生效的问题；继续复用现有 EvaluationService、Pi Durable 与资源池。
2. `src/evaluation/service.ts` 将启动恢复和控制命令同键重试统一为“读取当前意图 → 对齐 Pi 控制”。旧暂停回执晚到不能覆盖后续继续或取消，原命令身份和控制事件不重复创建。
3. `src/runtime.ts` 仅在真实 `paused → running` 转换时重设排队期限；重复继续和普通启动对齐不能不断延长任务等待时间。
4. `src/application.ts` 把 `onlineQueueReserve` 透传至业务队列，显式 `0` 和较高保留量均按配置准入；默认值及同一份模型池不变。
5. `src/pipeline.ts` 只允许同字段、同空值方向的 `is_null/is_not_null` 删除冗余 `value:null`；改变字段、运算符、其他过滤值、删除整个条件或删除非 null 操作数仍拒绝。提示词说明空值谓词不带 value，流水线签名同步变化，首次候选与编译失败继续保留。
6. `OperationRecord.dispatchedAt` 在授予发送权的同一 Pi 提交内记录，并与当次 `updatedAt` 相同；准备输入不能指定该字段。模型速率计量恢复由网关据此处理，本字段本身不代表远端接受或结束。
