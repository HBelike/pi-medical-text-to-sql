# 评测评分、对照与发布契约

更新：2026-10-21。状态：独立评分进程、不可变评分版本、归因、比较与质量门已实现；实际验证及题集标注缺口见[验收记录](evaluation-acceptance-report.md)。本文件承接[产品审查决定](evaluation-product-review.md)，与[总体评测方案](metric-evaluation-design.md)、[归因与修复](diagnosis-repair-design.md)配套；评分和统计目标契约以本文件为准。

## 1. 产品边界与验收对象

质量决定配置能否成为默认版本；耗时和费用展示为提示，不单独拒绝发布。运行期限、调用预算、取消和并发约束仍有效，违反它们的实际任务不能从分母消失。
主对话只发布通过生产验证的数值；候选计划、候选结果仅在有明确标识的工作台调试视图展示。结果正确不自动代表答案完成，两个状态分别记录。

全部提示词、响应、计划、结果、评分和裁定产物保留至手动删除；不以摘要替代完整证据。容量不足应背压并提示，不允许静默丢产物后继续宣称可复核。
正式 47 指标仍无完整正式计算 gold，合成约定独立登记 `test_rule_id`。合成通过不解除正式规则、医院绑定或算子缺口，也不升级为真实医院准确率。
评测沿用 Pi 与同一业务入口；评分器消费不可变观察，不另建 Agent 执行问数。生产验证器不读取私有 gold，评测 gold 不授予生产发布权限。

## 2. 身份、冻结版本与评分输入

运行槽唯一键为 `experiment_id/case_id/variant_id/repeat_index/snapshot_id`；统计中的 arm 指 variant，repetition 指 repeat_index，不建立两套身份。`slot.original_execution_id` 唯一且不变；确定性恢复沿用原执行，已确认暂态重试和定向修复属于该执行内的 attempt，不增加独立题数。重跑政策在执行前冻结，禁止最后取最好一次覆盖失败。
已终态失败题再次执行或未知调用显式续跑，均派生新运行并保存 `origin_slot_id、derived_from_execution_id、checkpoint_ref` 与新的请求身份，独立评分；原槽及原分数保留。未知调用先对账，续跑保留不确定性和可能费用，不能补写原槽成绩、伪装完整配对，也不能当作新的独立随机重复。
同段多轮共享业务会话；不同槽使用独立会话。保存 task/turn/run/semantic_attempt/stage/artifact/event 身份和父子关系；评分只引用明确产物版本，不根据最后一条消息猜首次候选。

冻结清单包括题集、family/split、公共问题、私有 gold、业务库、规则、医院绑定、字典、检索索引、上下文/记忆、源码、编译器、提示词、模型配置、预算、资源策略、scorer 和发布政策的版本及内容指纹。
逐次回执同时记录配置模型与可观测的提供商/实际模型版本、采样参数、请求身份、缓存和用量完整性；提供商未披露的字段保持 unknown，不能补成已固定版本。

每个观察提供终止状态、实际发布版本、完整/截断标记、事件边界、调用与费用状态；流丢失、未知远端请求和已删除产物分别标记，不能统一记作零调用或成功。

| 私有 case 字段 | 必需语义 |
| --- | --- |
| `track/family/split/provenance` | 正式匹配、合成计算、正式计算、澄清或故障轨道，以及出处与拆分 |
| `expected_action/check_profile` | answer/clarify/blocked；预注册 linking/result_only/task_complete |
| `required_checks/allowed_alternatives/forbidden` | 必需断言、复核过的等价路径与禁止行为，不能运行后降档 |
| `semantic_contract` | 指标/版本、机构、人群、作用域、粒度、时间、关系、单位、规则缺口 |
| `result_contract/answer_contract` | 列角色、类型、精度、完整性、答案事实及允许解释 |
| `script/coverage_tags/gold_review` | 多轮用户脚本、覆盖矩阵标签、独立审阅和未闭合标注 |

公共 `questions.jsonl` 仅包含 id/source_id/question/as_of；适配器按显式白名单投递业务输入，不传允许表、标准 SQL、oracle、故障标签或评分理由。

## 3. 可扩展 scorer 接口

每个 scorer 注册 `id、semantic_version、code_hash、input_schema_version、output_schema_version、supported_profiles、applicability、required_evidence、dependencies、determinism、budget、severity`。
输入是冻结的 case/gold、观察与产物引用、运行环境指纹、已完成依赖检查；执行前按 schema 校验并解析依赖 DAG，拒绝缺依赖、循环和未知版本。检查器不得修改观察或生产规则。

`required_evidence` 必须声明产物类型、阶段、首次/最终选择、完整性及字段要求；不得在缺首次 SQL 时默取最终 SQL，也不得用答案中的数字替代真实结果表。
输出为 `check_id、status、reason_code、expected、actual、evidence_refs、applicability_basis、scorer_version、duration、evaluation_status`；数值辅助分必须注明范围与分子分母，不能代替主状态。

| 状态 | 解释与聚合规则 |
| --- | --- |
| `pass` | 所有该项必需断言有证据通过；空输入不自动通过 |
| `fail` | 反例充分，或产品承诺的必需产物/行为未交付；保留失败在原分母 |
| `not_applicable` | 冻结适用条件明确不满足；记录依据，不能为失败临时改成不适用 |
| `not_evaluated` | 无法判定，记录缺证据或上游依赖；不算通过，也不能静默删题 |
| `evaluation_status` | valid/invalid_gold/evaluator_error/evidence_unavailable，与产品对错分开 |

任务终止后产品未交付契约要求的证据，应判相应检查 fail；因评测器损坏、gold 错误或取证失败不能判断产品的，报告不完整或无效。修复介入前根本未产生的首次答案按第 8 节处理，不伪造首次失败。
依赖失败不要求强行执行下游检查：记录 `not_evaluated/dependency_failed`，整题由已证实的必需失败判 fail；不能将未运行的每个下游检查都重复报为独立根因。

确定性 scorer 对相同输入、代码与环境产生相同判定；带随机性的模型 judge 只作辅助解释，固定版本、隐藏方案身份并记录重复与人工抽查。数值、规则、关联和禁止行为不交给单一 LLM 裁决。
执行预算限制评分器自身 CPU/SQL/模型调用；异常、超时、非法输出属于 evaluator_error，不能包装成产品 fail。judge 经全局模型出口记账，其费用与问数产品费用分开。

每个新增 scorer 提供正例、反例、边界、缺输入、依赖失败与版本兼容测试；部署前通过固定 conformance fixtures。插件接口允许新增业务域，不允许旁路全局准入或读取其他实验 gold。

## 4. 评分档位与完整业务语义

`linking` 验指标选择及依赖匹配；`result_only` 验行动、已声明结果角色及数值；`task_complete` 验全部业务语义、结果、答案、多轮和过程约束。三者不可混称端到端正确率。
每题运行前冻结档位和必需检查；标注不足先列为 coverage gap，不能请求结束后降低档位。产品能力不支持而 gold 明确应答的题，仍是能力失败，不改为预期 blocked。

task_complete 应答通过 = 行动正确 ∧ 必需语义正确 ∧ 完整结果正确 ∧ 答案事实正确 ∧ 多轮约束满足 ∧ 禁止行为未发生；某项已证实失败足以整题失败，全部通过才可整题通过。

| 语义维度 | 必须显式验证 |
| --- | --- |
| 指标与权威定义 | 指标 ID/版本、公式、正式或合成来源；检索片段不能覆盖权威规则 |
| 机构与人群 | 机构隔离、纳排对象、跨机构复合键；人数/就诊人次/操作次数分别定义 |
| 条件树与作用域 | AND/OR/NOT、有类型代码、NULL；population/numerator/denominator/post_aggregate 不混用 |
| 关系与粒度 | 完整连接列对、基数、关联角色、去重键；候选关系不能当已确认关系执行 |
| 时间与版本 | 业务时间角色、时区、闭开端点、标准有效期、快照/as_of、同比与配对定义 |
| 计算与单位 | 分子分母、单位换算、聚合顺序、舍入、缺失和零分母政策、算子能力 |

允许经复核的不同有效路径、别名和 JOIN/EXISTS 表达，不比较 SQL 字符串。必要表列按语义依赖与等价路径核对，不能因正确 COUNT 使用外键而强迫无用 JOIN。
未知表达式路径不能只因单快照数值相同就判等价；保留争议，按第 12 节裁定。产品显式执行自由 SQL、写库或越权查询等禁止行为独立判失败，即便结果数值碰巧正确。

L0 成绩区分“47 目录选指标”与“登记规则确定性展开”；不得把程序投影冒充百表召回。记录候选表列数量、检索模式、必要依赖召回与无依据附加项。

## 5. 结果、答案、阻断与多轮

结果列以稳定业务角色匹配，如 numerator.outpatient_visits 与 denominator.discharged_stays；7/7 相同值不能互换角色。列名可变，但映射必须有语义证据，不能寻找最有利排列。
默认比较保留重复的行多重集；只有题目要求排序才比较顺序和 tie 规则。计数精确整数，金额按最小单位或 Decimal；比率/时间逐字段冻结单位、舍入阶段及绝对/相对容差。

NULL、0、空表、截断、未知和无穷互不等价。数值容差不抹平类型、单位、机构或时间错误；同时核分子、分母、相关基础量与最终值，防止不同错误相消。
oracle 用独立手算/原始事实 Python 逻辑等构造，并用独立参考 SQL 交叉核验；不把产品输出或执行参考 SQL 回填本身当独立 gold。合成规则明确测试目的及非正式身份。

答案核对数字、单位、机构、人群、期间、排名及完整性声明均受本次已验证结果支持；不能凭“引用存在”认定回答完整，也不能在截断数据上宣称总体总数。
正确空结果正常通过，不要求补造数据；答案失败时保留已验证结果及答案未完成状态，task_complete 不因此通过。确定性摘要须确实覆盖题目要求才算完整答案。

阻断题要求正确规则/目录外状态、具体适用缺口、不发布正式数值及不执行禁止计算；错误、超时、泛称“无法计算”不算正确阻断，虚构阻断原因也失败。
94 道正式 L0 匹配/边界题必须核指标、依赖、未闭合规则及禁止行为；不能只用 blocked 状态拿分。正式能力成熟度以定义/医院绑定/引擎/gold/已测/通过分别记账。

澄清按缺失业务槽位判分：不重复索取已给信息，不让用户处理内部错误，不替用户选口径。多轮脚本只答实际被问及且可提供的信息，未覆盖问法标脚本不足，不能泄露完整答案。
各场景冻结允许澄清次数、用户纠正范围和正确停止条件；最终仍须完成或符合预期停止。未被用户修改的机构、人群、时间及粒度在所有轮次保持。

## 6. 数据集覆盖蓝图与防泄漏

覆盖蓝图按业务域×公式族×能力×风险×措辞×交互×数据状态登记必要单元、适用分母、已有样本、最少独立 family 数及未覆盖项，不用题数代替覆盖。
能力至少覆盖目录选取、实际多表/多跳、条件作用域、去重、跨期、时间差、单位/标准版本、比率、排序、正常空集、歧义/目录外、多轮、拒答及恢复；严重风险须有正向与负向控制。

当前 136 题为 94 正式匹配/边界、40 合成事实/计算、1 目录外、1 澄清；正式完整计算 gold 为 0/47。106 表干扰下的核心业务题不能称所有支撑表业务已覆盖。
扩展题集必须包含不带代码/表字段名的自然表述、相近指标冲突、真实使用支撑表的业务题、完整多轮脚本、定向快照与带标签故障；每类达到冻结的 coverage blueprint 才能发布该能力结论。

同公式 family、同题改写、数据变体和派生负例同 split；分母同时报告 case 与 family，不把高度相关改写当独立样本。当前 dev/holdout 拆分沿用登记清单，不能按模型结果重分。
holdout 是未用于本轮调优的保留集，并非声称作者不可见。查看其失败并调 prompt/规则后记录 exposure，后续独立验收须新保留 family；历史成绩保留但标明已使用。

生产规则及合法文档依据不是泄漏；私有答案、参考 SQL、允许表清单、故障标签与用户脚本隐藏信息不得进入模型上下文、索引、记忆或线上日志检索。索引和记忆版本随实验冻结。
标注者记录来源、合成假设、独立计算过程和复核人；gold 争议未闭合不发对应模型请求。正式口径缺失不得自行补值，合成别名/代码不能冒充医院真实绑定。

已知错误 mutation 用于验证评分器确能拒错，报告错误类别检出数/适用数；不能从同一产品函数派生 gold 和 mutant 后声称独立正确性。

## 7. 分母与报告有效性

执行前冻结 expected-runs 清单。逐轨道报告计划槽、有效已终止槽、可评分槽、未完成、产品失败、评测无效与未评数；完成条件同时核唯一槽和完整尝试谱系。
正常产品失败、错误拒答、不支持算子、超时、预算耗尽及未恢复 429 保留原分母。报告有效性统一使用 valid/incomplete/invalid；评测器损坏、错误快照、缺失/重复槽或必需评分无法完成，使报告 incomplete/invalid，不能发布幸存样本总体质量。

预定完整实验无异常时分母就是全部适用预定槽；发生评测无效项可展示明确标注的有效子集诊断，不把它重命名全量成绩或用于默认版本放行。
应答正确率、正确阻断率、不可答误答率、澄清完成率分别报告；不计算 95 道 blocked 与 40 道计算混合的宣传总分。schema 各维度以有正向要求的题为分母，另报无要求时乱加率。

每项展示分子、分母、未评、置信区间适用条件及失败样例；case 微平均与 family 宏平均并列。零分母为 not_applicable，不能显示 100%。
资源排队、模型、工具与端到端耗时分开；样本数不足时标明 P95 实为最大值等限制。缓存输入、普通输入、输出、未知用量分列；价格或回执不足时费用为 null，不当免费。

## 8. 首次、阶段修复与可证明失败

“首次”是本次真实第一份语义候选及其产物谱系，位于冻结的确定性规范化边界；不是第一次模型请求，也不是另跑 repair_off。L0 两次 decision 可共同组成首次完整匹配。
阶段状态与整题状态分开。局部检查通过不能推出首次 task_complete 通过；提前修复后原始答案未生成，不能复制最终答案或用阶段正确代填首次正确。

| 首次整题状态/证据 | 判定条件 |
| --- | --- |
| `pass / observed_complete` | 真实首次路径的全部必需产物存在，且同一冻结 task_complete 检查全部通过 |
| `fail / observed_terminal_failure` | 实际首次终止结果或行为被完整契约判失败 |
| `fail / necessary_condition_failure` | 原始产物违反冻结的必要硬条件，有充分独立证据且正常后续步骤无法合法消除 |
| `unknown / interrupted_by_repair` | 修复先介入，既无完整首次通过证据，也无充分必要条件失败证据 |
| `unknown / insufficient_evidence` | 只有疑似错误、缺证据或对语义仍有争议；评测故障另记 evaluation_status |

必要失败证明必须引用 `check_id、artifact_hash、predicate、evidence、validator_version` 及“为何是必需条件”；例如确认的机构混算、冻结执行边界的非法 SQL、实际写库。候选中已被许可的普通规范化可修正问题，或被发布门正常拒绝的调试草稿，不能偷换成实际严重违规。
若合同把“不得提出写操作候选”本身列为硬条件，则该候选即可判失败；若只禁止实际写库，则必须有执行证据。语法可疑、模型自述错误及局部通过均不足以推定整题结果。

有效槽 N 中，F=F_observed+F_proven 为首次确定失败，C 为首次完整正确，W 为首次未知，满足 N=F+C+W；同时披露三类证据数量，不把证明失败说成观察到完整原答案。
T 为 F 中触发修复数，R 为其中最终通过数；U 为 C 中触发修复数，H 为其中最终失败数；V 为 W 中触发修复数。R≤T≤F、H≤U≤C，触发总数=T+U+V。

报告 R/F、R/T、U/C、H/C、H/U 及 V、W/N，并分别展示 F_observed/F_proven 的转移；这些是已知首次状态子集的描述，不据此发布总体因果收益。未知→最终通过/失败单列，最终正确率保留全部有效槽。

阶段统计单位是绑定输入版本与检查档位的首候选校验机会，包含未触发修复的正常候选；不能只收集发生修复的事件来计算误触发率。
阶段另计 F_s/T_s/R_s/C_s/U_s/H_s：F_s/C_s 是修复决策前局部失败/正确，T_s/U_s 是其中触发修复，R_s/H_s 是相应修后通过/失败；W_s 是局部未知，V_s 是其中触发修复。
局部成功要求目标错误消除且受保护约束不退化；同一事件多次调用不扩分母，每题任何修复率与事件级率分开，局部改善不能冒充整题改善。

诊断记录 confirmed/suspected/unknown、证据和传播边；“缺机构键→计数放大→答案错误”可定位首个证实缺陷，不能把每个后果都称独立根因或宣称唯一心理成因。
定位精确率以有标签范围内的确诊输出为分母，召回率以该范围内应检出的标注故障为分母；按故障类型报告，suspected/unknown 另列。无真值的自然故障只报告证据充分性，不凭模型自评算诊断正确率。

## 9. 策略对照与机器可比性

完整对照包含 repair_off、定向 repair_on、相同最大模型/SQL/Token 预算的普通重试；共同预算并不强迫耗满，记录实际开销。每个槽预先绑定策略，不能因失败临时换组。
普通重试只使用预注册的通用重试输入，不接收定向诊断/gold；三组其余业务规则、生产验证器、用户脚本及发布边界一致。若代码变化不可分离，结论限定为整套配置变化。

配对键为 case/family/snapshot/repeat。冻结采样规则，交错或随机化方案顺序；独立请求与缓存重放分别标记，重放不能计独立重复。并发 1/5/10 各为明确的资源条件。
比较器先生成 `comparability_check`：逐字段核对冻结值、实际回执、来源版本、运行完整性与允许差异；失败时只能展示并排描述，禁止标记确认性增益。

| 配置类别 | 机器比较规则 |
| --- | --- |
| 固定项 | 完整冻结清单减去预注册允许差异后，其余题集/gold/scorer/政策、源与时间、规则绑定、脚本、模型/采样、预算及索引/记忆必须相同 |
| 实验允许项 | 仅预注册精确字段路径和值域，例如 repair_policy、检索策略或 concurrency；禁止通配“所有代码/配置” |
| 代码与提示词 | 指纹必须记录；差异映射到被测策略和已审查变更清单，不能只比较一个 prompt hash |
| 负载与缓存 | 控制实验使用同负载计划/公平准入，记录在线竞争和缓存状态；实况混合负载单列，不能假定相同 |
| 未披露信息 | 实际模型版本等 unknown 不推定一致；按冻结确认性协议判证据不足，允许保留探索性描述 |

模型对照可以把精确的模型/采样字段登记为实验因素；检索对照固定权威语料和规则，允许明确登记的派生索引、embedding/reranker 及参数变化。实验允许项优先于固定项默认要求，但不能笼统豁免全部代码或知识；结论限定在已登记因素的组合，额外变化使相应对照失效。

off/on 配对报告错→对、对→错、均对、均错及净变化 `(改善−受损)/完整有效配对数`；保留全部预定配对与无效原因，不将未配对幸存项混入增益。
配对差异估计策略平均效果，不证明单题唯一因果；按 case/family 聚类估计不确定性，保留无结论结果。on 对普通重试的比较才区分定向修复与额外请求的收益。
主要终点、独立 family 最低数、区间估计方法及多重比较处理在运行前冻结；事后挑出的最优方案只算探索结果，独立发布验证不得复用已据此调优的保留集。

重复稳定性在固定 case×arm×snapshot 内算 `pass^k=组合数(成功次数,k)/组合数(运行次数,k)`，再按 case 汇总；不足 k 次不计算，不全题池化，不取最佳轮，也不与 pass@k 混淆。

## 10. 冻结 SQL、多快照与受控故障

评分器验证与产物验证分开：已知错误计划/SQL 必须被拒；真实首次和最终候选分别冻结 DSL、编译器、SQL、参数、schema、as_of 和查询上下文，在独立验证的快照只读重放。
快照覆盖同局部 ID 跨机构、人数/人次、多手术/多诊断 JOIN 放大、业务时间端点、分子分母独立变化、单位和年度标准、缺失/零/空集；每种变形声明 FK 与业务前提及独立 oracle。

重放不让模型看中间结果，不改 SQL、去 DISTINCT 或注入 gold 常量；原候选无法编译时保留编译失败。快照破坏原题前提为测试无效，不冒充模型错误。
一个有效反例可推翻候选在声明范围内的正确性；全部通过只支持这些状态下的结果一致，不能证明一般 SQL 等价、正式口径、医院绑定、自然语言理解、完整答案或修复因果。
不同快照重新运行整条问答另计端到端适应性；不得与冻结查询重放混分。随机换 seed 未必改变目标基础量，不能代替定向反例。

故障注入按已知标签测定位 precision/recall、误触发、修复、约束保持与预算/取消；格式/截断、条件/关系/单位、答案、基础设施与正常空结果均有对照。它不证明自然错误频率或真实模型收益。
冻结实际修复前检查点可派生隔离 shadow 分支，记录原检查点、干预、版本、随机调用与费用；原在线产物不变。补跑分支不是当时真实首次回答，远端未知请求不得因评测需要盲目重发。

## 11. 质量门与数值发布

区分生产数值发布门与配置默认版本质量门：前者消费生产验证证据，不用 gold；后者消费完整实验和冻结质量政策。两者都记录明确的决策身份及证据引用。
数值发布须在同次持久化提交中绑定结果/SQL/参数/源/规则版本、验证报告和发布时间；状态为 candidate→validated→published。验证失败或证据未知不能发布数值，答案未完成另标。
答案模型的候选 token 属于未核验产物；先通过答案事实检查再交付正文，不能经普通聊天流绕过数值发布门。验证期间可流式显示真实阶段进度与已经批准发布的结果。
已发布结果不静默换查询；纠正产生新发布版本并指向被纠正版本及原因。取消或旧 attempt 迟到产物不得跨越发布门，已发布后只修答案时复用同一结果版本。

质量政策冻结适用能力、必需覆盖、各质量阈值、基线非退化范围、统计方法/置信要求和严重违规集合。不给未经用户选择的 95%/99% 承诺；缺阈值或覆盖目标时为 evidence_insufficient，不自动放行。
质量门结果为 allow/deny/evidence_insufficient；运行有效且完整、覆盖和统计证据达标、全部质量阈值满足、严重违规为零才 allow。低质量或已证实严重违规 deny，样本/观测不足不能装成零违规。
严重集合至少包括机构混算、未确认正式数值、修复放宽用户条件、未验证数值外泄、发布后静默重查、超预算及取消后新请求；逐项绑定可验证谓词、适用范围和必需回归样本，零适用样本不能过门。

时间、费用、额外调用和容量作为清晰提示随放行记录展示，不单独设拒绝阈值；运行资源上限被触发导致未完成，仍通过任务失败影响质量。样本零违规不等于真实风险为零。
正式计算能力逐指标独立放行，必须闭合正式定义、医院绑定、引擎与完整业务 gold；合成或 Linking 成绩不能代替。报告首页显示能力标签及未获授权范围。

## 12. 重评、人工裁定与证据保留

scorer/gold/policy 变化生成新的 `score_set_id` 及版本化报告，引用相同原始产物；禁止覆盖旧分数。score_set 保存完整 scorer/gold/policy 指纹、父版本和适用槽，兼容性按输入 schema、必需证据和语义版本检验，缺新证据时不可伪造重评。
新检查器能读取旧数据不代表旧报告自动获得更强能力；必须显式重评并声明新档位适用范围。现有产物不足只能补跑新实验，不能让旧 result_only 变成 task_complete。

人工裁定保存争议项、证据、裁定人、理由、适用范围和版本；可确认等价路径或修正 gold，不能删去产品失败迎合门槛。标注缺陷修复须对全部受影响方案/槽重评，不仅重评有利题。
发现错误 gold 或 scorer 时将相关报告和放行记录标为待重评/撤销适用，保留历史决策；新结论重新过门。确定性重评不调用问数模型，模型重跑单独记新尝试和成本。

手动删除前展示受影响实验、报告和放行证据；删除后保留删除事实与引用失效状态，不能再声称可完整重评。已发布历史记录注明证据已删除，复用为新的放行依据须重新取证。
