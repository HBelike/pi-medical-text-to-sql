# L0 百表数据底座变更总结

更新：2026-10-19。模块设计、调用链、交付内容与边界见 [数据底座说明](l0-benchmark-data.md)；已有开源方法的取舍见 [调研记录](l0-benchmark-research.md)。

- 目标：按已有 47 项 L0 规范反向生成多表事实和问题，为后续问答评测准备独立数据包；未扩展 Pi 核心、查询算子或修复流程。
- `python/l0_benchmark_core.py` 沿原 26 表/216 列契约生成三机构、跨两年事件；修正纵向时间、死亡带药、家庭病床、手术级别及取消就诊收入矛盾，保留缺失、去重、跨期和版本边界。
- `python/l0_benchmark_support.py` 新增 80 表/10 业务域，明确计划、实际发生与账务确认等不同粒度，复合外键保持机构隔离；每表非空。
- `python/build_l0_benchmark.py` 与 `fixtures:l0-benchmark` 入口生成默认 106 表、693 列、136,742 行；固定种子/规模可配置，目录拒绝覆盖，六份原 L0 文件按字节冻结并记录哈希。
- 导出 `.local/l0-benchmark-v1/` 中 SQLite、完整 DDL、中文字典、表目录、合成约定、逐指标覆盖、输入及产物哈希；当前来源清单和服务未变更，提供两个符合现有读取契约的数据源条目供后续合并。
- `python/l0_benchmark_questions.py` 生成 136 题：47 匹配、47 正式计算边界、30 事实查询、10 显式合成计算、2 目录外/澄清；40 数值题中 18 道多表，按业务族分开发 110/保留 26。
- 公共题仅 4 字段；私有 gold 用原始行独立 Python 运算，再对照 SQL，附规则、缺口及错误变形。模型字典不含 gold/测试角色；运行知识采用原生 `global_rules.field_values` 契约并保持值类型。
- 46 项 Python 定向检查通过：核心 13、支撑 11、题目 15、包集成 7；覆盖时序、数量、外键、非空、跨目录复现、DDL 重建、只读答案生成、原输入不变和公共/私有分离。
- 5 项 Node 原生兼容检查通过：真实生成临时库并走 `DomainService`、`L0Knowledge`，106 表加载、47 项投影与原阻断、代码类型校验、基础 COUNT 及指纹保持均通过；仓库根及应用静态检查通过。
- 默认库实测 SQLite 完整性通过、外键错误 0；40 道 SQL 与独立答案一致、9 个手算锚点通过、5 个错误变形被识别。未执行 LLM、构建或全量测试，不将夹具验证当作模型质量得分。
- 后续：接入适配新公共题/私有 gold 的评测器，按实际失败补算子，再确认正式口径与医院绑定。47 项原阻断和缺口保留；保留集非第三方盲测，合成分布不代表真实医院。
